    처음 시작하기

    제어판은 GPU 노트북에서 돌아가는 웹 페이지입니다. 버튼을 누르면 GPU 노트북이 로봇과 카메라를 직접 움직이고, 이 브라우저는 화면 역할만 합니다.

    1. 점검하기로 로봇, 모터, 카메라, 다른 사용자 여부를 확인합니다.
    2. 카메라 켜기로 global 카메라에 팔로워와 작업 공간이 다 들어오는지 봅니다.
    3. 로봇 옆 사람이 리더와 팔로워 자세를 맞추고, 맨 위 안전 확인란을 체크합니다.
    4. 텔레옵 시작으로 조작을 연습합니다.
    5. 텔레옵을 중지하고 녹화 시작으로 학습 데이터를 모읍니다.
    6. 녹화 다시보기로 잘 찍혔는지 확인합니다.

    로봇은 한 번에 한 사람, 한 프로그램만 제어할 수 있습니다. 텔레옵과 녹화는 동시에 실행되지 않습니다.

    제어판 여는 방법

    • 바탕화면 아이콘: "OMX Control Panel"을 더블클릭합니다. 서버를 켜고 연결한 뒤 크롬 새 창으로 엽니다.
    • 터미널: 내 노트북 터미널에서 omx-panel을 입력합니다.
    • VS Code Remote-SSH: GPU 노트북 터미널에서 omx-panel 실행 후, 포트(Ports) 탭의 8765에서 지구본 아이콘을 누릅니다.

    주소 127.0.0.1:8765는 SSH 연결을 통해 GPU 노트북으로 이어집니다. 내 노트북을 재부팅했다면 위 방법으로 다시 여세요. 브라우저를 닫아도 실행 중인 텔레옵이나 녹화는 계속됩니다.

    안전 확인

    텔레옵과 녹화는 시작하면 팔로워가 리더 자세로 움직입니다(안전 시작으로 천천히). 그래서 맨 위 확인란을 체크해야만 시작 버튼이 동작합니다.

    • 로봇 옆에 사람이 있어야 합니다. 원격에서는 주변이 보이지 않습니다.
    • 리더와 팔로워 자세가 크게 다르면 엘보 모터에 과부하가 걸릴 수 있습니다.
    • 팔로워 주변에 걸릴 물건이 없어야 합니다.
    • 팔로워 전원 공급기를 바로 뽑을 수 있는 곳에 둡니다.

    안전 시작: 시작하면 팔로워가 ① 저장한 시작 자세로 팔을 들고 ② 그리퍼를 닫은 뒤 ③ 리더 자세로 천천히 다가갑니다. 이 동안 모터 출력은 30%로 제한됩니다. 다가가는 중에 리더를 잡고 움직이기 시작하면 바로 원래 출력과 속도로 따라잡습니다. 리더나 팔로워의 회전 관절이 한 바퀴 넘게 읽히면 자동으로 보정하고, 둘의 차이가 너무 크면(약 160° 이상) 시작하지 않고 이유를 알려줍니다. 녹화는 이 과정이 끝난 뒤에 시작됩니다.

    안전 정지: 중지하면 ① 저장한 끝 자세로 천천히 옮기고 ② 모터 출력을 3초에 걸쳐 줄인 뒤 ③ 토크를 끕니다. 그래서 팔이 툭 떨어지지 않습니다. 정지에 몇 초 걸리며, 그동안 상태가 "천천히 내려놓는 중"으로 보입니다. 이때 중지를 한 번 더 누르면 바로 끝나지만 토크가 켜진 채 그 자세로 멈춥니다.

    시작 자세·끝 자세 저장(텔레옵 칸): 리더암을 손으로 원하는 자세로 잡고 저장 버튼을 누릅니다. 리더 위치만 읽고 로봇은 움직이지 않습니다. 시작 자세는 그리퍼가 바닥에서 충분히 떨어진 "팔을 든 자세", 끝 자세는 "팔을 접어 작업대에 내려놓은 자세"로 정합니다. 처음 쓰기 전에 꼭 저장하세요.

    • 각 영상 아래 숫자는 밝기입니다. "검은 화면"이 뜨면 렌즈 캡, 가림, USB를 확인합니다.

    • 화면 고정(기본 켜짐): 아래로 스크롤해도 카메라 칸이 왼쪽 위에 붙어 따라 내려옵니다. 녹화 버튼과 영상을 한 화면에서 보며 작업할 수 있습니다. 다시보기·로그를 볼 때 가리면 체크를 끄세요. 좁은 창(한 줄 배치)에서는 고정하지 않습니다.

    카메라 위치 맞추기: 카메라 칸 아래를 펼치고 기준 데이터(학습에 쓴 녹화)를 고르면, 그 첫 화면이 front 영상 위에 반투명으로 겹쳐 보입니다. 아래 문구가 "학습 때와 같은 위치입니다"가 될 때까지 카메라를 옮기세요. 카메라 위치가 바뀌면 모델은 처음 보는 장면으로 받아들여 성공률이 크게 떨어집니다.

    텔레옵

    • 텔레옵 시작: 안전 시작(팔 들기 → 그리퍼 닫기 → 천천히 리더 자세로) 뒤 리더를 따라 움직입니다. 데이터는 저장되지 않습니다.
    • 상태 칸에 경과 시간과 제어 주기(정상은 약 60Hz)가 표시됩니다.
    • 중지: 안전 정지(끝 자세로 이동 → 출력 서서히 줄이기 → 토크 끄기)로 끝냅니다. 몇 초 걸립니다.
    • 기본은 카메라 없이 실행합니다. 화면은 왼쪽 카메라 보기로 확인합니다. Rerun 보기를 켜면 카메라를 포함해 실행하고 영상을 Rerun으로 보냅니다.

    학습 데이터 녹화

    1. 데이터셋: 새로 만들거나, 내 기존 데이터셋을 골라 이어서 녹화합니다.
    2. 새 데이터셋 이름: 현재 시각 MMDD_HHMM이 미리 채워집니다. 고쳐 써도 됩니다.
    3. 작업 설명: 영어 한 문장입니다. 같은 데이터셋에서는 항상 같은 문장을 씁니다.
    4. 에피소드 수 / 시연 시간 / 원위치 시간을 정하고 녹화 시작을 누릅니다.

    녹화는 "녹화 중"과 "원위치 시간"을 번갈아 반복합니다. 원위치 시간은 저장되지 않으니 이때 물체를 제자리에 놓습니다.

    버튼하는 일
    다음으로지금 단계를 바로 끝냅니다. 시연이 일찍 끝났거나 원위치를 마쳤을 때 누릅니다
    이번 것 다시 찍기방금 에피소드를 버리고 다시 찍습니다. 실패한 시연은 꼭 다시 찍으세요
    녹화 끝내기 (저장)완료된 에피소드까지 저장하고 끝냅니다. 진행 중이던 에피소드는 버려집니다

    음성 안내를 체크하면 이 노트북 스피커로 "에피소드 N 녹화 시작", "물체를 원위치하세요", "저장 완료"를 알려줍니다.

    Hugging Face 자동 업로드를 체크하면, 녹화가 정상으로 끝난 뒤 huggingface.co/datasets/<HF 아이디>/omx_<첫 키워드>_<MMDD_HHMM>에 비공개로 올립니다. 키워드는 설명과 작업 문장을 보고 자동으로 정합니다. 예를 들어 "딸기를 집어 접시에 놓기"는 strawberry, pick_place, plate가 되고, 첫 키워드가 이름에 들어갑니다. 키워드는 태그로도 붙고, 설명·작업 문장·에피소드 수·카메라 구성·녹화 시각이 데이터셋 페이지에 표로 정리됩니다. 강제 종료했거나 에러로 끝난 녹화는 올리지 않습니다. 업로드는 공유 폴더 저장 다음에 따로 하므로, 실패해도 녹화 데이터는 남아 있습니다. 처음 한 번은 터미널에서 ssh -t omx-gpu '~/venv/il/bin/hf auth login'으로 로그인해야 합니다. 이때 Write 권한 토큰이 필요합니다.

    처음엔 에피소드 2~3개로 짧게 시험하고, 다시보기로 확인한 뒤 본 녹화를 합니다. 학습에는 보통 50개 이상이 필요합니다.

    녹화 다시보기

    1. 데이터셋에서 고릅니다. 공유 폴더의 팀 전체 데이터셋이 나옵니다.
    2. 에피소드 버튼을 누르면 그 에피소드가 열립니다.
    3. 재생: front와 wrist가 함께 재생되고, 에피소드 끝에서 멈춥니다.

    재생 위치 막대로 넘겨볼 수 있고, 처음으로 버튼과 0.5배~4배 속도 조절이 있습니다. 영상 아래에 작업 설명과 프레임 수가 나옵니다.

    확인할 점: 팔로워가 화면 밖으로 나가는지, wrist 영상이 검은지, 사람 손이 찍혔는지, 실패한 시연이 섞였는지 봅니다.

    예전에 녹화한 데이터셋은 이 데이터셋 Hugging Face에 올리기 버튼으로 나중에 올릴 수 있습니다. 진행 상황은 녹화 칸 아래에 표시됩니다.

    ② 학습 시키기

    1. 학습 데이터 고르기: 녹화 원본에 체크합니다. 빠른 선택으로 전체 선택·선택 해제·날짜별 선택을 할 수 있고, 짧은 에피소드 빼기는 데이터셋마다 길이 중앙값의 60%보다 짧은 에피소드(중간에 끊긴 시연 등)를 뺍니다.
    2. 영상 보며 고르기: 이름을 눌러 에피소드를 펼친 뒤 에피소드를 누르면 아래에서 front·wrist 영상이 2배속으로 재생됩니다. 실패한 시연이면 학습에서 빼기(단축키 X)를 누르고, 다음 ▶(→)으로 넘기며 훑어봅니다. 스페이스는 재생·멈춤입니다.
    3. 학습 설정: 정책(ACT 추천), 스텝 수, 배치 크기, 이미지 증강을 정합니다. 아래에 예상 소요 시간과 데이터 반복 횟수, 저장 위치가 나옵니다.
    4. 바로 시작을 누르면 진행 막대, 남은 시간, 손실 그래프가 실시간으로 표시됩니다.

    학습 계획 (여러 학습 이어서 하기): 예를 들어 같은 데이터로 ACT를 먼저, 끝나면 Diffusion을 학습하려면

    1. 데이터와 ACT 설정을 고르고 계획에 추가, 정책을 Diffusion으로 바꾸고 다시 계획에 추가합니다.
    2. 오른쪽 학습 계획에서 계획 실행을 누릅니다. 위에서부터 하나씩 학습하고, 앞 학습이 끝나면 다음 학습을 자동으로 시작합니다. 다른 계정이 GPU로 학습 중이면 끝날 때까지 기다렸다 시작합니다.
    3. 계획은 GPU 노트북에 파일로 저장되고 제어판과 따로 돌아갑니다. 브라우저·SSH를 닫거나 제어판이 재시작돼도 계속됩니다.
    • 대기 중인 항목은 ▲▼로 순서를 바꾸거나 취소할 수 있습니다. 실행 중에 새 항목을 추가하면 맨 뒤에서 차례를 기다립니다.
    • 앞 학습이 실패하면(예: GPU 메모리 부족) 실패로 표시하고 다음 항목으로 넘어갑니다. 로그는 그대로 남고, 다시 넣기로 같은 설정을 맨 뒤에 다시 넣을 수 있습니다.
    • 실행 중인 학습을 학습 중지로 멈추면 기본은 계획 전체 일시정지입니다. 중지 버튼 옆 체크를 켜고 멈추면 다음 항목을 바로 시작합니다. 일시정지 버튼은 지금 학습은 끝까지 하고 다음 항목만 시작하지 않습니다.
    • 항목마다 결과 모델 경로, 최종 손실, 걸린 시간이 표시됩니다.
    • 같은 녹화·같은 에피소드 조합으로 합친 학습 데이터가 이미 있으면 새로 만들지 않고 그대로 씁니다.

    여러 데이터셋을 고르거나 에피소드를 빼면, 남은 에피소드로 <계정>/train_<키워드>_<MMDD_HHMM> 학습 데이터를 새로 만듭니다. 원본 녹화는 바뀌지 않습니다. 모델은 같은 시각을 붙여 /srv/il/checkpoints/<계정>/<정책>_<키워드>_<MMDD_HHMM>에 저장되므로, 이름만으로 짝을 찾을 수 있습니다.

    로봇은 움직이지 않으니 안전 확인이 필요 없습니다. 브라우저를 닫거나 제어판을 재시작해도 학습은 계속됩니다. GPU는 하나라서 한 번에 한 학습만 돌립니다. 다른 사람이 학습 중이면 바로 시작 버튼이 잠기고 누가 쓰는지 표시됩니다. 이때도 계획에 넣어두면 GPU가 비는 대로 시작합니다.

    학습 중지는 한 번 더 눌러야 실행됩니다. 멈추면 그때까지의 중간 저장은 남지만, 최종 모델과 기록 표 줄은 생기지 않습니다.

    ACT 기준 배치 8, 4만 스텝에 약 2시간입니다. 데이터가 20~50개라면 데이터를 30~80바퀴 도는 정도면 충분합니다. 손실 그래프가 평평해지면 더 늘려도 큰 차이가 없습니다.

    정책

    로봇이 카메라 영상과 관절 위치를 보고 다음 동작을 정하는 모델의 종류예요.

    • ACT: 시연 수십 개로 정해진 작업 하나를 정확하게 따라 하는 데 강해요. 학습이 빠르고 메모리도 적게 써요. 처음엔 ACT를 추천해요.
    • Diffusion: 동작이 부드럽고 여러 방식의 시연을 잘 섞어요. 대신 데이터가 더 필요하고, 학습이 몇 배 느리고, 이미지 2장(지금과 직전)을 함께 봐서 RAM도 2배 가까이 써요.

    정책을 바꾸면 배치 크기와 데이터 로딩 수가 그 정책의 기본값(ACT 8·8, Diffusion 16·4)으로 바뀌어요.

    스텝 수

    모델 가중치를 몇 번 고칠지예요. 한 스텝마다 배치 하나를 보고 조금씩 고쳐요. 많을수록 오래 배우지만 시간이 늘고, 너무 많으면 녹화 데이터만 외우는(과적합) 경우도 있어요.

    데이터를 몇 바퀴 보는지 = 스텝 × 배치 ÷ 전체 프레임 수. 아래 예상 칸에 바퀴 수가 나와요.

    참고: ACT 30,000~100,000, Diffusion 50,000~200,000. 손실 그래프가 평평해지면 더 늘려도 큰 차이가 없어요.

    배치 크기

    한 스텝에 함께 보는 프레임 수예요. 크면 학습이 안정적이고 같은 스텝에서 더 많은 데이터를 보지만, GPU 메모리와 RAM을 더 쓰고 스텝 하나가 느려져요.

    RAM이나 GPU 메모리가 부족하면 먼저 데이터 로딩 수를, 그래도 부족하면 배치를 줄이세요. 배치를 절반으로 줄이면 같은 바퀴 수를 보기 위해 스텝을 2배로 늘려야 해요.

    데이터 로딩 수

    녹화 영상에서 프레임을 꺼내 이미지로 바꾸고 증강해서 배치로 묶는 보조 프로세스(CPU) 개수예요. 많으면 GPU가 데이터를 덜 기다려서 빨라지지만, 프로세스마다 배치를 2개씩 미리 만들어 쌓아 두기 때문에 RAM을 많이 써요.

    학습이 RAM 부족으로 멈추면(로그에 DataLoader worker ... killed) 이 값을 먼저 줄이세요. 0이면 보조 프로세스 없이 학습 프로그램이 직접 읽어서 RAM은 가장 적게 쓰지만 아주 느려요.

    이미지 증강

    학습할 때 영상의 밝기·대비·색감·위치를 조금씩 무작위로 바꿔서 보여 주는 기능이에요. 조명이나 카메라가 조금 달라져도 모델이 덜 헷갈리게 돼요. 보통 켜 두세요.

    증강은 데이터 로딩 프로세스가 CPU로 처리해서, 켜면 스텝이 조금 느려질 수 있어요.

    예상 RAM·학습 시간

    예상 RAM은 정책·배치·데이터 로딩 수·카메라 수와 해상도로 계산하고, 이 GPU 노트북에서 실제로 잰 값으로 맞춘 숫자예요. 사용 가능은 지금 GPU 노트북에 남은 RAM이에요.

    • 초록: 넉넉해요.
    • 노랑(사용 가능의 70% 이상): 학습 중에 다른 일을 하면 모자랄 수 있어요.
    • 빨강(90% 이상): RAM 부족으로 학습이 죽을 가능성이 높아요. 시작 전에 한 번 더 묻고, 권장값 적용으로 줄인 값을 넣을 수 있어요. 학습 계획도 시작하는 순간 다시 확인해서, 모자라면 시작하지 않고 "메모리 부족 예상"으로 표시해요.

    GPU 메모리도 같이 보여요(지금 다른 프로그램이 쓰는 양 포함). 16GB를 넘으면 학습이 시작하자마자 "CUDA out of memory"로 멈춰요. 이때는 배치를 줄이세요. 예: SmolVLA 배치 64는 넘치고, 32는 약 10.6GB, 16은 약 7.2GB예요.

    RAM이 모자라면 리눅스가 학습 프로그램(때로는 화면·소리 같은 다른 프로그램까지)을 강제로 꺼요. GPU 메모리와는 다른 문제예요.

    예상 학습 시간은 같은 정책·배치·로딩 수로 했던 이전 학습의 스텝당 시간 × 스텝 수예요. 기록이 없으면 "알 수 없음"으로 나와요.

    학습 기록

    팀 전체의 학습이 번호순으로 누적됩니다. 칸에는 최근 3개만 간단히 보이고, 전체 기록 보기를 누르면 넓은 창에서 전체 표를 봅니다. /srv/il/checkpoints/INDEX.md와 같은 내용이고, 학습이 끝나면 자동으로 한 줄 추가됩니다.

    • 모델: 경로 복사를 누르면 평가할 때 --policy.path에 넣을 경로가 복사됩니다.
    • 학습 데이터 / 원본 녹화: 어떤 녹화의 몇 번 에피소드로 학습했는지 보여줍니다. 각 모델 폴더의 TRAINED_ON.md에도 같은 내용이 있습니다.
    • 중간 저장 지우기: 내 학습만, 최종 모델이 있을 때만 보입니다. 1만 스텝마다 저장된 중간 결과(하나에 약 600MB)를 지우고 최종 모델은 남깁니다.
    • 비고: 학습 시작 때 쓴 메모가 들어갑니다. 평가 결과 같은 나중 메모는 모델 폴더의 summary.json 안 note에 적고 새로고침하세요.

    3. 안전 확인란을 체크하고 평가 시작을 누릅니다. 모델을 불러오는 데 몇 초 걸립니다.

    처음 자세로 돌아가기

    평가는 리더 팔 없이 모델이 팔로워를 움직이기 때문에, 텔레옵처럼 "리더 자세로 돌아오기"가 없어요. 대신 평가를 시작할 때 팔로워가 있던 자세(처음 자세)를 기억해 두었다가 그 자세로 돌려보내요.

    • 평가를 끝낼 때 (평가 끝내기, 또는 정해진 시도를 다 마쳤을 때): 처음 자세로 천천히 이동 → (켜 두면) 그리퍼를 처음 상태로 천천히 열기 → 출력을 3초에 걸쳐 줄이고 토크 끄기. 팔이 툭 떨어지지 않아요.
    • 원위치 시간 (켜 두면): 시도가 끝날 때마다 처음 자세로 돌아가요. 팔이 작업 영역에서 비켜서 딸기를 놓기 쉽고, 다음 시도가 녹화 때처럼 같은 자세에서 시작해요. 돌아가는 중에 다음으로를 누르면 이동을 멈추고 바로 다음 시도로 넘어가요.
    • 움직이는 동안 출력은 30%로 제한되고 속도는 느려요(안전 정지와 같은 설정).
    • 그리퍼: 딸기를 잡은 채 멈췄을 수 있어서, 팔이 처음 자세에 도착한 다음에만 그리퍼를 열어요. 가는 도중에 아무 데나 떨어뜨리지 않아요. 끄면 잡은 채로 있다가 토크가 꺼질 때 힘이 빠지며 풀려요.
    • 돌아가지 않는 경우: 어떤 관절이 처음 자세와 약 160° 넘게 다르거나 위치가 한 바퀴 어긋나게 읽히면, 위험할 수 있어 움직이지 않고 출력만 천천히 줄여요.
    • 즉시 중단 (처음 자세로): 모델을 바로 멈추고, 지금 시도를 저장하지 않고 곧바로 같은 방식으로 처음 자세로 돌아가요. 평가 끝내기보다 빨리 출발해요. 프로그램이 멈춰 응답이 없으면(5초) 강제로 끝낸 뒤, 평가 시작 때 저장해 둔 처음 자세 파일로 복귀 프로그램이 다시 연결해서 돌아가요. 이때도 토크를 끄지 않고 지금 자리에서 출발해서 팔이 튀지 않아요.
    • 비상 정지 (제자리)는 한 번 누르면 바로 아무 데도 움직이지 않고 토크를 켠 채 멈춰요. 기록은 저장되고, 버튼이 [홈 위치로 이동]으로 바뀌어요. 사람 손이 팔 근처에 있으면 이쪽을 쓰고, 손을 치운 뒤 [홈 위치로 이동]을 누르면 위 과정(처음 자세 → 그리퍼 → 출력 감소 → 토크 끔)을 이어서 해요. 프로그램이 응답하지 않아 강제로 끝난 경우에도 같은 버튼으로 돌아가요.

    처음 자세는 평가마다 새로 기억해요. 녹화 시연이 시작하던 자세(홈)에 팔로워를 두고 평가를 시작하면, 시도마다 같은 자세에서 시작할 수 있어요. 텔레옵·녹화는 바뀌지 않았어요(저장된 끝 자세가 있으면 그리로 갑니다).

    평가 방식 (자유 위치 / 지정된 위치)

    모델마다 물체를 같은 자리, 같은 순서에 놓고 평가해야 공정하게 비교할 수 있어요. 지정된 위치 방식은 front 카메라 화면 위의 점 N개와 순서를 저장해 둔 거예요(예: "지정된 위치 10곳"). 자유 위치는 예전처럼 위치를 정하지 않고 평가해요. 팀 전체가 같이 쓰고, 작업마다 따로 만들 수 있어요(딸기, 면세품 등).

    1. 평가 설정의 평가 방식에서 지정된 위치를 고르면 시도 횟수가 위치 수(예: 10)로 들어가고, 카메라 미리보기가 켜져서 평가를 시작하기 전에 첫 위치(#1)가 노란 원으로 보여요. 딸기를 원 안에 놓고 "목표와 Npx"가 초록이 되면 [평가 시작]을 누르세요. 시작하면 미리보기는 꺼지고 평가 영상 위 표시로 이어져요.
    2. 평가 중 실행 화면의 front 영상에 노란 원(다음 시도 목표)과 번호, 다른 위치(흰 점), 참고 물체(그릇, 파란 점선 원)가 겹쳐 보여요. 원위치 시간에 물체를 노란 원 안에 놓으세요.
    3. 빨간 물체(딸기)는 자동으로 찾아 십자로 표시하고 목표와의 거리를 알려 줘요. 초록(8px 이내) 좋음, 노랑(20px 이내) 조금 벗어남, 빨강은 다시 놓으세요. 기준은 평가 방식마다 정할 수 있어요(기본 8·20px). 시도가 시작되는 순간의 위치와 거리가 기록돼요. 물체는 감지 범위(주황 점선 사각형) 안에서만 찾아요. 로봇 베이스의 빨간 부품처럼 늘 보이는 빨간 물건은 범위 밖에 두세요. 아주 작은 빨간 점(150px² 이하)은 무시해요.
    4. 모든 위치를 시도하면 저장하고 자동으로 끝나요.

    이 표시는 화면에만 그려지고 녹화 영상에는 들어가지 않아요. 녹화는 평가 프로그램이 카메라에서 직접 하고, 화면은 그 복사본 위에 브라우저가 덧그린 거예요.

    결과 표시: 시도마다 위치 번호와 거리가 나오고, 성공·실패·무효를 눌러요. 무효는 사람이 개입했거나 물체를 잘못 놓은 경우예요. 성공률에서 빠지고, 평가 중이면 그 위치를 다음 시도에서 다시 해요(여분 시도 3번까지). 실패를 누르면 실패 단계(다가가기·잡기·운반·놓기·시작 오동작·기타)가 그리퍼 움직임으로 자동 추정돼 "추정: …"으로 보이고, 고를 수 있어요.

    위치 편집: 화면을 클릭해 위치를 추가하고, 끌어서 옮기고, ▲▼로 순서를 바꿔요. "참고 물체"로 바꾸고 클릭하면 그릇 같은 기준 물체를 점선 원으로 넣어요. 상자·봉투처럼 색으로 찾을 수 없는 물체는 "감지 안 함"으로 하면 목표 원만 그려요.

    학습 후보 (평가 시도를 학습 데이터로)

    성공한 평가 시도도 학습 데이터로 쓸 수 있어요. 특히 한 번 놓쳤다가 다시 잡아서 성공한 시도(리커버리)는 사람 시연에 잘 없는, 배워야 할 동작이에요. 반대로 여러 번 헤매다 성공한 시도는 그 헤매는 습관까지 배우게 되니 추천하지 않아요.

    • 추천1 한 번에: 한 번에 잡고, 오래 멈추지 않고, 시간도 보통인 시도
    • 추천2 리커버리: 두 번째에 잡은 시도. 평가의 첫 시도는 안전 시작(천천히 다가가기)이 영상에 들어 있어 최대 추천2예요
    • 비추천 헤맴: 세 번 이상 잡거나, 오래 멈추거나, 시연 평균보다 1.5배 넘게 걸린 시도

    배지 옆 근거(잡기 횟수 · 가장 긴 멈춤 · 길이)를 보고 영상으로 확인한 뒤 "학습 후보"를 체크하세요. 기본은 꺼짐이고, 체크한 것만 학습에 들어가요. [추천 모두 선택]·[1순위만 선택]으로 한 번에 고를 수 있어요. 실패·무효 시도는 고를 수 없어요.

    체크한 시도가 있는 평가는 ② 학습 탭 데이터 목록에 [평가 후보]로 나와요. 고르면 체크한 시도만 다른 녹화와 합쳐져 학습되고, 어떤 종류가 몇 개 들어갔는지 학습 기록에 남아요(나중에 넣은 모델과 뺀 모델을 비교).

    지정된 위치는 모델을 재는 자리예요. 그 위치의 시도를 학습에 쓰면 다음 평가에서 점수가 실제보다 좋게 나올 수 있어서, 체크할 때 한 번 물어봐요.

    모델 비교

    같은 평가 방식(지정된 위치)으로 평가한 결과를 위치 × 평가 표로 보여 줘요. 칸마다 O(성공)·X(실패)와 실패 단계, 물체를 놓은 위치와 목표의 거리가 나와요. (추정)은 자동 판정이라 사용자가 고르지 않은 값이에요.

    • 열 머리에 모델 이름과 평가 설정(정책, 비동기·smooth, DDIM 단계, CPU 스레드, 실제 제어 속도)이 있어요. 설정이 다르면 같은 조건의 비교가 아니니 주의하세요.
    • 아래 줄에 모델별 성공률(무효 제외)과 실패 단계별 개수, 오른쪽 열에 위치별 성공 수가 있어요. 모든 모델이 실패하는 위치는 데이터가 부족한 위치일 가능성이 커요.
    • 터미널에서 python omx_compare.py compare <세트ID> --save로 CSV·JSON 파일도 만들 수 있어요.

    비동기 실행

    모델은 한 번 계산할 때 앞으로 할 동작 여러 개(동작 묶음)를 한꺼번에 만들어요. 보통은 그 묶음을 다 쓰고 나서야 다음 묶음을 계산하기 때문에, 계산하는 동안 로봇이 멈춰요. Diffusion은 1초 넘게 멈추기도 해요.

    비동기 실행을 켜면 남은 동작을 계속 실행하면서 뒤에서 다음 묶음을 미리 계산해요. 새 묶음이 오면 이미 지나간 부분은 버리고 이어서 써요. 로봇이 멈추지 않아 동작이 부드러워져요.

    • 한 번에 쓸 동작 수 (actions_per_chunk): 한 묶음에서 실제로 쓸 동작 개수예요. 30개 = 1초. 너무 길면 오래된 판단으로 움직이고, 너무 짧으면 계산이 자주 돌아요. 기본: ACT·SmolVLA 50, Diffusion 15(최대). 15개 미만으로 줄이면 묶음이 자주 바뀌어(0.5초에 한 번 이상) 이음새가 많아지고 오히려 더 버벅일 수 있어요.
    • 다음 계산 시작 시점 (chunk_size_threshold, 0~1): 남은 동작이 이 비율 아래로 줄면 다음 묶음 계산을 시작해요. 0.5면 절반쯤 썼을 때 시작해요. 계산이 오래 걸리는 모델일수록 크게(일찍) 하세요.
    • 겹치는 구간 합치기 (aggregate_fn): 새 묶음과 아직 남은 옛 묶음이 겹치는 부분을 어떻게 합칠지예요. 가중 평균(옛 30% + 새 70%)이 부드럽고 무난해요. "새 것만"은 반응이 빠르지만 바뀌는 순간 튈 수 있어요.

    평가 중 로그에 [omx] async: 줄로 계산 시간과 "큐가 비어 기다린 횟수"가 10초마다 나와요. 기다린 횟수가 늘면 계산이 동작보다 느린 거예요. 다음 계산 시작 시점을 키우거나 Diffusion이면 추론 단계 수를 줄이세요.

    ACT의 "부드럽게 실행"(시간 앙상블)은 매 스텝 계산하는 다른 방식이라 비동기 실행과 함께 쓰지 않아요. 안전 시작, 처음 자세 복귀, 즉시 중단, 비상 정지, 평가 기록은 비동기 실행에서도 똑같이 동작해요.

    RTC (실시간 청킹)

    비동기 실행에서 새 동작 묶음이 오면 옛 묶음과 겹치는 부분을 평균 내는데, 두 묶음이 서로 다른 길을 계획했으면 평균이 어색하거나 이음새에서 살짝 튈 수 있어요.

    RTC는 새 묶음을 계산할 때부터 "계산하는 동안 이미 실행될 동작"과 "아직 남은 동작"을 모델에 알려줘서, 새 묶음이 그 끝에서 자연스럽게 이어지도록 만들어요. 그림을 이어 그릴 때 앞부분을 보고 이어 그리는 것과 비슷해요.

    • SmolVLA 전용이에요(LeRobot의 RTC는 flow matching 모델인 SmolVLA·pi0·pi0.5에만 들어 있어요). Diffusion은 지원하지 않아요: Diffusion의 동작 생성 함수는 RTC의 "이어 붙이기 안내"를 받는 부분이 없어서, 켜도 아무 효과가 없어요. ACT도 마찬가지예요. Diffusion에서 묶음이 바뀔 때 튀면 출력 부드럽게(필터)를 켜거나 다음 계산 시작 시점을 키워(예: 0.7) 겹치는 구간을 늘려 보세요.
    • 이어 붙일 구간 (execution_horizon): 옛 묶음 중 몇 개 동작에 맞춰 이을지예요. 기본 10.
    • 이어 붙이는 세기 (max_guidance_weight): 클수록 옛 동작에 더 딱 맞춰 이어요. 기본 10. 너무 크면 새 판단이 늦게 반영돼요.

    출력 부드럽게 (필터)

    모델이 낸 관절 목표를 로봇에 보내기 바로 전에 부드럽게 다듬어요(지수 이동 평균). 동작 묶음이 바뀌는 순간 목표가 갑자기 튀는 것을 줄여요. ACT·Diffusion·SmolVLA, 동기·비동기 모두에 쓸 수 있어요.

    • 세기: 약·중·강 = 목표를 따라가는 데 약 0.05·0.1·0.2초 늦어져요. 셀수록 부드럽지만 빠른 동작이 둔해지고, 너무 세면 목표 지점에 늦게 도착해요. 중부터 시험해 보세요.
    • 그리퍼: 기본은 필터를 걸지 않아요(잡고 놓는 타이밍이 늦어지면 안 되니까요). "그리퍼에도 약하게"를 켜면 약 1프레임만 늦춰요.
    • 녹화되는 action은 필터를 거친 값(실제로 로봇에 보낸 값)이에요. 평가 기록과 모델 비교표에 세기가 남아요.
    • 시도마다 필터는 새로 시작해요(첫 목표는 그대로).

    매끄러움은 분석 자료와 비교표의 지표(멈춤 비율, 평균 |가속도|, 명령 튐 비율)로 비교할 수 있어요.

    추론 단계 수 (Diffusion)

    Diffusion은 잡음에서 시작해 동작을 여러 번 조금씩 다듬어서 만들어요. 학습할 때 기본은 100번이라, 한 묶음을 계산하는 데 이 노트북에서 약 1.2초가 걸려요(그동안 로봇이 멈춤).

    여기서 단계 수를 줄이면 재학습 없이 같은 모델을 빠른 방식(DDIM)으로 돌려요. 10단계면 약 0.12초예요. 보통 10~20단계면 결과가 거의 같아요. 너무 적으면(1~3) 동작이 거칠어질 수 있어요.

    비동기 실행과 함께 쓰면 계산하는 동안에도 로봇이 계속 움직여서 가장 부드러워요.

    SmolVLA

    SmolVLA는 여러 사람이 공개한 저가 로봇팔 데이터로 미리 학습된 모델(lerobot/smolvla_base)을 우리 데이터로 조금 더 학습(미세조정)해서 써요. 카메라 영상과 함께 작업 문장(예: "Pick up the strawberry and put it in the bowl")도 읽어요.

    • 처음부터 배우는 ACT보다 처음 보는 물체 위치에 더 잘 대응할 수 있어요(보장은 아님, 평가로 비교).
    • 우리 카메라 front·wrist는 모델의 camera1·camera2로 자동 연결돼요.
    • 추천: 배치 16, 스텝 20,000. 예상 시간과 메모리는 설정 아래 상자에 나와요.
    • 평가할 때는 비동기 실행과 RTC를 켜면 부드러워요.

    CPU 스레드 수

    평가할 때 카메라 이미지 전처리 같은 CPU 계산을 몇 개로 나눠 동시에 처리할지예요. 모델 추론은 GPU가 하기 때문에 이 값은 결과(정확도)는 바꾸지 않고 속도만 바꿔요.

    값이 너무 크면 작은 일을 너무 잘게 나누고 서로 기다리느라 CPU를 다 써 버려요. 그러면 제어가 초당 30번을 못 맞추고 로봇이 끊겨요. 너무 작으면 계산이 느려져요.

    스레드제어 속도 (부드럽게 켬)CPU 사용
    1~830Hz 유지약 3~4코어
    24 (예전 기본)약 23Hz, 매번 느림약 22코어

    기본값 4는 이 GPU 노트북에서 측정해 가장 안정적이었던 값이에요. 평가 중에 "제어 속도 ○Hz / 목표 30Hz" 경고가 뜨면 먼저 학습 같은 다른 작업을 멈추고, 그래도 뜨면 이 값을 2나 8로 바꿔 보세요.

    멈췄을 때 복구

    두 버튼 모두 실수 방지를 위해 한 번 더 눌러야 실행됩니다.

    • 강제 종료: 중지를 눌러도 끝나지 않거나 다음 실행이 안 될 때 씁니다. 실행 중인 텔레옵·녹화와 하위 프로세스를 즉시 끝내고 포트, 카메라, 잠금을 풉니다. 팔로워는 토크가 켜진 채 자세를 유지합니다. 녹화 중이었다면 진행 중이던 에피소드는 저장되지 않습니다.
    • 모터 초기화: 강제 종료 후에도 모터가 응답하지 않거나 점검에서 하드웨어 에러가 나올 때 씁니다. 두 팔의 모터 12개를 재부팅해 에러를 지웁니다. 토크가 즉시 풀려 팔로워가 떨어지므로, 팔을 내려둔 상태에서만 누릅니다. 내려둘 수 없으면 옆 사람이 팔을 받친 상태에서 누릅니다.

    그래도 "에러 남음"이 나오면 팔로워 전원(12V)을 껐다 켭니다.

    Rerun으로 보기 (선택)

    녹화 중에는 카메라를 녹화 프로그램이 쓰고 있어서 제어판 카메라 화면이 꺼집니다. 녹화 중에도 영상과 관절 그래프를 보려면 Rerun을 씁니다.

    1. 내 노트북 터미널에서 source ~/venv/il/bin/activate 후 rerun을 실행해 창을 띄워둡니다.
    2. 제어판에서 "Rerun으로 보내기"를 체크하고 내 노트북 Tailscale IP를 넣습니다. 확인은 tailscale ip -4로 합니다.
    3. 텔레옵이나 녹화를 시작하면 Rerun 창에 나타납니다.

    Rerun 버전은 GPU 노트북과 같은 0.26.2여야 합니다.

    로그

    실행 중인 텔레옵·녹화의 출력이 실시간으로 나옵니다. 문제가 생기면 여기의 마지막 줄들을 확인합니다. 전체 기록은 GPU 노트북의 ~/il_ws/omx_logs/에 실행할 때마다 파일로 남습니다.

    "Headless environment detected", "pynput" 경고는 원격 실행이라 키보드 단축키를 끈다는 뜻입니다. 정상이니 무시하세요. 같은 기능은 녹화 버튼으로 합니다.
